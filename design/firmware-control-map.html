How the Zynthian rig connects

One stereo pair per Pisound

Standard Pisound provides one stereo audio input and one stereo audio output, plus DIN MIDI in and out. All units on that Pi share those jacks. More independent stereo sends or returns need more audio I/O or another Pi.

Controllers and audio take separate paths

Push, OXI, or Tracker can supply MIDI to the selected instrument. Push or Tracker audio can feed the effects chain. OXI supplies notes, clock, and controls rather than audio. Choose one clock leader for the rig.

Instrument lane or effects lane

A synth takes MIDI and makes audio. An effect takes audio from an earlier unit or the physical input. For an external send/return, use a wet-only effects path and blend at the source. Multiple external sources share the input pair through a mixer or a source choice.

Sound, rig and scene

Use an engine preset for a sound, a snapshot for the whole rig, and ZS3 for scenes within that rig. Configure Program Change routing explicitly so scene recall does not consume an instrument’s intended program messages.

MIDI output needs its own route

T-1 needs to send notes to an instrument; MIDI-capable ZOIA patches may need the same. Zynthian provides MIDI-chain routing; our T-1 and ZOIA wrappers still need their LV2 MIDI outputs implemented and tested. A physical MIDI-out socket alone does not provide that route.

Multiple Pis, one control language

Give each Pi a clear destination name, such as Voices or Space. Select the destination Pi, then the active unit and section. Keep the same control order on each controller. The proposed 16-control external surface is optional. Its four groups of four can guide Zynthian parameter pages; mappings still need validation.

Design assumptions: Zynthian on Pi 5 with the existing Pisound, subject to image and hardware validation. These are proposed connections, not a statement that every firmware is ready to host. References: Pisound connections · Zynthian chains and recall · Rig design.
